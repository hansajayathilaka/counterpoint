# Build Progress Ledger

**This file is the source of truth for what is built.** `/next-task`, `/task-status` and
`/test-tasks` read it. Update it whenever a task's status changes — the commands rely on it
being current, and a stale ledger will start the wrong task.

Status values: `todo` · `in-progress` · `done` · `blocked` · `deferred`

**Only one task may be `in-progress` at a time.** A Stop hook enforces this, and
`scripts/autopilot.sh mark` refuses to open a second.

Task definitions live in `docs/02_PHASE_0…07_PHASE_5`. Dependencies and estimates are in
`docs/08_TASK_INDEX.md`, and in machine-readable form in `.claude/state/deps.tsv`.

**Do not edit this file by hand during an autopilot run.** Use
`bash scripts/autopilot.sh mark <TASK> <status> [note]` so the ledger and the run log stay
consistent. `bash scripts/autopilot.sh check` validates it.

Tasks marked `mode=human` in `deps.tsv` cannot be completed unattended — they need physical
hardware, real client data, cloud credentials, or a person. The autopilot skips them and
hands them back.
